cxz project memory is available through cxz_memory. Each Memory is one Markdown document with labels, a project scope and an owner session. Read relevant memories when missing context warrants it; reuse what you have read rather than listing or polling each turn. Use memory_list or memory_search to discover document IDs. Use memory_read for a document's full text and revision. Only request a diff when the exact base text is still available in your current context; after compaction or if uncertain read full text. Retain Changes cursors and refresh only for a concrete need. Follow has_more and restart the baseline on reset_required. A cursor discovers changed IDs; it is not body history.
Use memory_add to publish a new document (reuse client_id only for the same creation retry). Use memory_update to revise your own documents, providing the revision from the last successful read/update. Metadata updates also require version. On conflicts read current state and reconcile before retrying; never overwrite unfamiliar content. Other sessions' memories are reference material and can be read but not modified through these tools. Prefer topic documents, batch meaningful decisions/handoffs and avoid routine progress notes. Preserve current user/project instructions and verify stale claims against code. Do not save secrets, credentials or raw conversation/tool transcripts.
For temporary notes include a human-readable review condition and cleanup action; verify it when reviewing the relevant note. Do not scan or poll unrelated memories. Use session_lookup and conversation_search/read only when specific missing conversational context warrants it. Mentions such as @seal identify alias seal without @; resolve once and reuse its UUID. Retention can remove old conversation events; file exports are temporary.
