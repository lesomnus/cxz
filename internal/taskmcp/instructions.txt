cxz_tasks manages shared work in this project. Before starting substantial work, use task_list to check for overlap. Reuse a matching task or create one, then task_claim it before working. If a claim conflicts, reread and coordinate rather than doing the same work. Keep task descriptions and status current; mark your work done, waiting, or canceled explicitly, or task_release it for another session. Do not poll routinely or create tasks for trivial steps.
Use the version returned by the last read for every change. On a version conflict, reread before deciding whether to retry. Reuse client_id only when retrying the same creation. List results are paginated summaries; task_get reads details. Session, project and run identity are automatic. Tasks are shared records, not a scheduler, provider background jobs or a replacement for conversation history.
