# 대화 스크롤 경험의 기준

핸들과 사용자 입력 막대의 기준 구현은 `39ad43a`이다. 2026-10-05 사용자가
현재 움직임을 유지하고 싶다고 확인한 상태다. 아래 규칙과 테스트를 함께 사용해
다른 UI 수정 후에도 이 경험을 재현한다. 그림자나 고정 입력 UI는 별도 레이어이며,
핸들의 물리 동작과 본문의 가상 높이를 바꾸지 않는다.

## 사용자가 느끼는 동작

- 평소에는 스크롤 표시가 숨는다. 대화 영역에 들어오면 얇은 핸들과 그 왼쪽의
  사용자 입력 위치 막대만 나타난다. 오른쪽 끝 52px 안으로 접근하거나 핸들을
  잡으면 핸들이 가로로 두 배 두꺼워진다. 세로 길이나 읽는 위치는 바뀌지 않는다.
  처음 최신 대화를 표시할 때는 최종 위치에 즉시 배치해 핸들이 레일을 가로질러
  날아오지 않는다.
- 휠 이동은 빠르게 반응하면서 짧게 이어지고, 요청한 위치에서 정확히 멈춘다.
  작은 트랙패드 입력은 운영체제 동작을 따른다. 내용이 없거나 실제 끝에서
  바깥 방향으로 휠을 돌리면 아무 변화가 없고 Latest도 잠깐 나타나지 않는다.
- 표시하는 범위는 전체 기록보다 작다. 범위 안에서 핸들은 읽는 위치를 가리키고
  막대는 사용자 입력 사이의 상대 배치를 유지한다. 새 범위가 들어오면 핸들과
  막대가 하나의 애니메이션으로 함께 재배치된다. 막대가 휠 방향으로 거꾸로
  따라오는 현상은 없어야 한다. 범위가 유지되는 동안 막대가 정지하는 것은 정상이다.
  예를 들어 휠을 아래로 움직여 범위가 교체되면 막대와 핸들은 위로 함께 정렬되고,
  휠을 위로 움직여 교체되면 아래로 함께 정렬된다. 범위 안에서 핸들만 읽는 위치를
  따라가는 이동과 이 재배치 애니메이션을 구분한다.
- 범위 밖으로 당길 때 핸들은 가장자리에 머문다. 더 당길수록 마우스를 따라오는
  정도는 줄고 본문 이동 속도는 빨라진다. 본문이 계속 이동하면 막대도 해당
  가장자리를 통과하는 내용과 같은 위상으로 흐른다. 핸들은 뷰 밖으로 나가지 않는다.
- 당긴 상태에서 레일로 돌아오면 현재 읽는 위치에서 바로 이어진다. 처음 잡기
  전의 범위나 최신 대화로 돌아가지 않는다. 놓으면 장력이 풀리고, 핸들과 모든
  막대가 같은 시간에 새 범위로 부드럽게 정렬된다.
  범위 애니메이션 중에 잡더라도 실제 그려진 핸들 위치에서 시작한다.
- 화면 밖 내용을 처음 측정하거나 이전/다음 페이지가 교체되어도 현재 메시지와
  화면 내 위치가 유지된다. 이미 표시하던 막대 배치가 높이 측정 때문에 흔들리지
  않는다. 최근 대화에서 조금 위로 갔다가 돌아올 때도 작은 점프가 없어야 한다.

## 재현 절차

```sh
npm run --prefix ts sandbox
```

1440 × 1000 Chromium에서 **Long history**를 열고 다음을 확인한다.

1. 다른 스크롤 없이 처음 핸들을 잡아 위로 충분히 당긴다. 더 오래/멀리 당길수록
   본문은 빨라지고 핸들 변위는 덜 증가한다. 막대도 본문 진행에 맞춰 움직인다.
2. 잡은 채 레일 안으로 4px 들어온 뒤 8px 더 이동한다. 읽던 곳에서 조금 이동하며
   최신 대화로 돌아가지 않는다. 놓았을 때 핸들과 막대의 정렬 속도가 같다.
3. 기록 중간에서도 아래쪽 끝으로 같은 과정을 반복한다. 양 끝 최대 장력에서도
   핸들 위/아래가 대화 뷰 안에 남아 있고 실제 기록 끝에서는 내용이 더 이동하지 않는다.
4. 휠로 ±1200px씩 80회 왕복한다. 페이지 교체를 지나도 같은 입력의 막대가
   역방향으로 움직이지 않는다. 처음 측정하는 내용과 이미 측정한 내용에서 동일하다.
5. 최신에서 8px 올리고 4px 내린 뒤 각각 잠시 멈춘다. 각각 8px/4px 떨어진 위치를
   유지한다. 창 너비를 900px로 바꿔도 읽던 메시지의 화면 위치가 유지된다.
6. 스크롤 없는 **Project checklist**에서 양 방향으로, **Long history** 최신 끝에서
   아래 방향으로 휠을 움직인다. Latest 버튼이 한 프레임도 나타나지 않는다.
7. reduced-motion 설정에서 이동이 보간되지 않는지, 코드 블록 등 내부 스크롤과
   가로/확대 휠이 정상 동작하는지 확인한다.

## 구현 수치와 보존해야 하는 연결

| 항목                   | 기준                                                      |
| ---------------------- | --------------------------------------------------------- |
| 메시지 위치 좌표       | 메시지마다 100 unit; 실제 DOM 높이와 분리                 |
| 최대 표시 범위         | `min(logicalMax, viewportHeight × 12)` unit               |
| 범위 유지 구간         | 내부 20–80%; 실제 기록 끝에서는 해당 끝까지 유지          |
| 새 범위 애니메이션     | 160ms, `1 - (1 - t)^3`; 핸들/모든 막대 공통 RAF           |
| 휠/레일 안 드래그 응답 | 각각 24ms / 12ms 지수 응답; 잔차 < 1px에서 목표에 고정    |
| 프레임 시간 상한       | 32ms                                                      |
| 장력 변위              | `sign(d) × 20 × (1 - exp(-abs(d)/80))` px                 |
| 장력 속도              | `sign(d) × viewport × min(16, (abs(d)/60)^1.4 × 2)` px/s  |
| 레일 여유              | 위/아래 `8 + 20`px; 장력 최대 변위 20px                   |
| 핸들                   | 최소 높이 32px; 표시 폭 4px → 접근/드래그 때 8px          |
| 입력 막대              | 핸들 왼쪽, 폭 10px / 높이 2px                             |
| 표시 전환              | opacity/가로 scale 160ms; 좌표별 CSS transition 금지      |
| 기록 캐시/렌더         | 초기 최신 256개, 최대 512개, 페이지 128개; 보이는 행 ±6개 |

`messageMap`의 변환은 단조이며 역변환이 가능해야 한다. `RowKnot`은 행 높이가
바뀌어도 현재 읽는 행 내부의 비율을 보존한다. `history-shift`는 휠 목표와 본문
픽셀 좌표에, `mapping-shift`는 핸들 범위와 메시지 좌표에 적용한다. 두 좌표계를
섞으면 페이지 경계에서 막대가 흔들린다.

휠/드래그가 본문을 움직인 즉시 `reading-move`로 가상 목록의 anchor를 갱신한다.
브라우저의 나중 scroll 이벤트만 기다리면 ResizeObserver가 이전 프레임의 위치를
복원할 수 있다. 캐시 경계나 높이만 바뀌면 범위를 그대로 보존하고, 재배치는 실제
읽는 위치의 이동 방향으로만 허용한다. 막대는 seq를 key로 유지하고, 레일 밖에서도
캐시에 남은 노드는 유지해야 범위 교체 애니메이션이 이어진다.
본문에 별도의 CSS `scroll-behavior: smooth`를 추가하면 이 보간과 겹치므로 사용하지
않는다. 키보드 Arrow는 48px, PageUp/PageDown은 한 뷰 높이, Home/End는 실제 끝으로
이동하며 진행 중인 휠 보간을 중단한다.

## 회귀 검증

```sh
npm run --prefix ts test
npm run --prefix ts sandbox:build
npm run --prefix ts test:sandbox
```

- `navigation.spec.ts`: 최초 장력 복귀, 단조 휠/정확한 정착, Latest 순간 생성 감시,
  캐시 교체 중 막대 target/표시 좌표의 역방향 이동(<1px) 검사.
- `scroll.spec.ts`: hover/접근/장력, pointerup 순간을 기준으로 핸들과 막대의 공통
  애니메이션 진행률 차이(<0.12) 검사.
- `tension.spec.ts`: 양쪽 끝에서 지속되는 막대 위상과 핸들 경계 검사.
- `virtual.spec.ts`: 전체 기록 왕복, 캐시/DOM 상한, 작은 최신 근처 이동, resize anchor.
- `scroll-physics.test.ts`, `virtual-layout.test.ts`: 물리 곡선, 범위 보존, 메시지↔픽셀
  단조 변환/역변환, 행 재측정 시 읽는 비율 보존.

본문 이동량을 검사할 때는 누적 `history-shift`를 뺀다. 놓는 순간의 좌표는
pointerup capture에서 기록한다. 툴 호출 사이에도 장력 스크롤은 계속되므로
나중에 기록한 좌표를 시작점으로 쓰면 서로 맞는 애니메이션을 실패로 판단할 수 있다.

고정 입력은 본문 흐름과 가상 높이에 공간을 추가하지 않는다. 가상 목록 밖의
고정 레이어에서 제목 블록 바로 아래, 대화 열과 같은 폭으로 표시한다. 현재 위치
앞의 입력이 상단을 지나면 대상이 바뀌지만 상자의 위치는 스크롤 좌표와 무관하다.
다음 입력이 이전 상자를 밀어내지 않는다.

뷰 상단 양쪽에 같은 거리 조건을 적용한다. **현재 보이는 가장 위의 사용자 입력
상자 상단**과 뷰 상단 사이의 거리, 그리고 **마지막으로 위로 지나간 입력 상자
하단**과 뷰 상단 사이의 거리 중 작은 값을 사용한다. 상단에 일부만 걸친 입력은
거리 0이다. 캐시에 없는 이전 입력이나 현재 보이는 입력이 없는 쪽은 거리를
제한하지 않는다. 어느 쪽이든 96px 이하면 고정 입력을 숨긴다.
96~128px에서는 smoothstep으로 하단 노출 높이(0~8px)와 opacity(0~1)를 함께 늘리고,
양쪽 모두 128px 이상이면 하단 8px를 전부 보여준다. 따라서 아래쪽 입력이 멀어질
때와 본문이 위로 이동하면서 마지막 입력이 지나갈 때 같은 노출 경험을 갖는다.
opacity와 transform은 180ms ease-out으로 전환해 입력 상자가 완전히 화면 밖으로
빠지거나 cache/측정으로 거리가 바뀌어도 갑자기 나타나지 않는다. 완전히 숨긴 동안은
inert/aria-hidden으로 마우스 접근 영역과 버튼의 클릭/focus를 막는다.

하단이 드러난 상태에서 대화 열의 상단 28px 영역에 마우스가 들어오거나
버튼이 키보드 focus를 받으면 180ms ease-out으로 전체 상자가 내려온다. 펼친 상자
안에 마우스/focus가 있는 동안 유지하고 벗어나면 다시 접는다. 숨긴 부분은 제목
영역 위로 그려지거나 클릭되지 않으며, 접힌 상태의 활성 영역 아래에서는 본문과
계속 상호작용할 수 있다. 터치로 상단 활성 영역을 누르면 focus로 펼친다.
Reduced motion에서는 전환 없이 즉시 펼친다. 높이는 180px와 뷰 높이의 25% 중 작은
값으로 제한하고, 긴 입력은 상자 내부에서 스크롤한다.

누르면 그 입력의 원래 위치로 이동하며, 캐시에서 빠진 입력도 필요한 페이지만
다시 읽는다. 그림자는 고정 입력과 스크롤바 아래에 그려져 이 컨트롤을 가리지 않는다.
`pinned-prompt.spec.ts`는 실제 휠 이동의 매 프레임에서 고정 레이어의 상단과 접힌
상자의 아래쪽 8px 위치를 검사하며 접근/focus 전환, 제목 영역 clipping, 클릭 이동,
캐시 밖 입력 조회와 긴 입력 내부 스크롤을 검증한다. 가까운 입력/상단에 걸친 입력
때의 비노출과 hit-test, 양쪽 거리 중간의 반투명/4px 노출과 왕복, 거리 변화의 중간 프레임 fade도
검증한다. 이 레이어의 표시 방식은 앞서
기록한 핸들/막대의 좌표, 장력과 공통 애니메이션 계산을 변경하지 않는다.

## Latest 툴바 오버레이

Latest는 대화 뷰 안에 떠 있는 텍스트 버튼 대신 composer 툴바 중앙의 아래 화살표다.
Send와 같은 폭64px/높이24px/radius7px/transparent 배경/hover#363636을 공유한다.
절대 위치 오버레이여서 flex 공간을 차지하지 않고, 이후 그 자리에 일반 툴바 버튼이
배치돼도 위에 표시된다. 기존 툴바28px/입력창 크기/Send 우측2px 여백은 유지한다.

처음과 최신 위치에서는 숨김이다. 과거 방향으로96px 스크롤하면 나타나고, 표시 중
최신 방향으로96px 스크롤하면 숨는다. 숨긴 뒤 다시 과거 방향으로96px 스크롤하면
나타난다. 숨김에서는 음수 scrollTop delta, 표시 중에는 양수 delta를 누적하며 작은
역방향 이동은 그 양을 빼고0에서 멈춘다. 임계값을
넘어 상태가 바뀌면 누적량을0으로 재설정한다. 따라서 같은 방향으로 계속 이동할 때
버튼이 반복해서 켜졌다 꺼지거나 작은 방향 반전마다 깜빡이지 않는다.

`Transcript.scrolled()`는 기존 motion.top을 기준으로 실제 native 픽셀 delta만
`onReadingMove`에 전달한다. `history-shift`가 이 기준 위치를 함께 보정하므로 캐시
페이지/row 재측정/anchor 복원의 좌표 변경은 이동량으로 세지 않는다. native scroll
이벤트가 중복 전달되면 delta0이며, 장력 상태나 onMotion의 감쇠 자체도 이동량이 아니다.
핸들/막대의 좌표 계산과 공통 애니메이션 물리는 바꾸지 않는다.

클립된 중앙 slot 안에서 버튼이 입력창 뒤의 translateY28px/opacity0 위치에서
translateY0/opacity1로180ms ease-out 전환된다. 숨긴 slot은 inert/aria-hidden이며
버튼이 입력창을 덮거나 클릭/focus를 가로채지 않는다. Reduced motion에서는 즉시
전환한다. 클릭은 type=button으로 최신 기록을 불러와 live follow를 재개하고,
작성 중인 draft를 보내거나 지우지 않는다.

`latest-toolbar.spec.ts`는 실제 휠80px에서는 비노출, 누적100px에서 중간 전환 frame,
