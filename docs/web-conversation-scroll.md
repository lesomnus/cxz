# 대화 스크롤 경험의 기준

사용자가 유지하고 싶다고 확인한 스크롤 경험을 기록한다. 다른 UI 수정 후에도
아래 동작과 회귀 검사를 함께 확인한다. 그림자나 고정 입력 UI는 별도 레이어이며,
핸들의 물리 동작과 본문의 가상 높이를 바꾸지 않는다.

수치와 곡선의 source of truth는 현재 코드다. 크기·시간·임계값·계수를 문서에
복사하지 않는다. 시각적 방향은 [웹 디자인 원칙](web-design.md)을 따른다.

## 사용자가 느끼는 동작

- 평소에는 스크롤 표시가 숨는다. 대화 영역에 들어오면 얇은 핸들과 그 왼쪽의
  사용자 입력 위치 막대만 나타난다. 핸들 가까이 접근하거나 잡으면 가로로
  두꺼워진다. 세로 길이나 읽는 위치는 바뀌지 않는다. 처음 최신 대화를 표시할 때는
  최종 위치에 즉시 배치해 핸들이 레일을 가로질러 날아오지 않는다.
- 휠 이동은 빠르게 반응하면서 짧게 이어지고, 요청한 위치에서 정확히 멈춘다.
  작은 트랙패드 입력은 운영체제 동작을 따른다. 내용이 없거나 실제 끝에서
  바깥 방향으로 휠을 돌리면 아무 변화가 없고 Latest도 잠깐 나타나지 않는다.
- 표시하는 범위는 전체 기록보다 작다. 범위 안에서 핸들은 읽는 위치를 가리키고
  막대는 사용자 입력 사이의 상대 배치를 유지한다. 새 범위가 들어오면 핸들과
  막대가 같은 애니메이션으로 함께 재배치된다. 막대가 휠 방향으로 거꾸로
  따라오는 현상은 없어야 한다. 범위가 유지되는 동안 막대가 정지하는 것은 정상이다.
  휠을 아래로 움직여 범위가 교체되면 막대와 핸들은 위로 함께 정렬되고,
  휠을 위로 움직여 교체되면 아래로 함께 정렬된다. 범위 안에서 핸들만 읽는 위치를
  따라가는 이동과 이 재배치 애니메이션을 구분한다.
- 범위 밖으로 당길 때 핸들은 가장자리에 머문다. 더 당길수록 마우스를 따라오는
  정도는 줄고 본문 이동 속도는 빨라진다. 본문이 계속 이동하면 막대도 해당
  가장자리를 통과하는 내용과 같은 위상으로 흐른다. 핸들은 뷰 밖으로 나가지 않는다.
- 당긴 상태에서 레일로 돌아오면 현재 읽는 위치에서 바로 이어진다. 처음 잡기
  전의 범위나 최신 대화로 돌아가지 않는다. 놓으면 장력이 풀리고, 핸들과 모든
  막대가 같은 시간에 새 범위로 부드럽게 정렬된다.
  범위 애니메이션 중에 잡더라도 실제 그려진 핸들 위치에서 시작한다.
- 화면 밖 내용을 처음 측정하거나 이전/다음 페이지가 교체되어도 현재 메시지와
  화면 내 위치가 유지된다. 이미 표시하던 막대 배치가 높이 측정 때문에 흔들리지
  않는다. 최근 대화에서 조금 위로 갔다가 돌아올 때도 작은 점프가 없어야 한다.

## 재현 절차

```sh
npm run --prefix ts sandbox
```

데스크톱 Chromium에서 **Long history**를 열고 다음을 확인한다.

- 다른 스크롤 없이 처음 핸들을 잡아 위로 충분히 당긴다. 더 오래/멀리 당길수록
  본문은 빨라지고 핸들 변위는 덜 증가한다. 막대도 본문 진행에 맞춰 움직인다.
- 잡은 채 레일 안으로 돌아와 조금 더 이동한다. 읽던 곳에서 이어지고 최신 대화로
  돌아가지 않는다. 놓았을 때 핸들과 막대의 정렬 속도가 같다.
- 기록 중간에서 아래쪽 끝으로 같은 과정을 반복한다. 양 끝 최대 장력에서도
  핸들이 대화 뷰 안에 남고 실제 기록 끝에서는 내용이 더 이동하지 않는다.
- 휠로 긴 거리를 반복 왕복한다. 페이지 교체를 지나도 같은 입력의 막대가
  역방향으로 움직이지 않는다. 처음 측정하는 내용과 이미 측정한 내용에서 동일하다.
- 최신에서 조금 올리고 내려 각각 잠시 멈춘다. 요청한 위치를 유지한다.
  창 너비를 바꿔도 읽던 메시지의 화면 위치가 유지된다.
- 스크롤 없는 **Project checklist**에서 양 방향으로, **Long history** 최신 끝에서
  아래 방향으로 휠을 움직인다. Latest 버튼이 순간적으로 나타나지 않는다.
- Reduced motion에서 이동이 보간되지 않는지, 코드 블록 등 내부 스크롤과
  가로/확대 휠이 정상 동작하는지 확인한다.

## 구현에서 보존할 관계

| 역할                                | 현재 기준 구현                                                                                           |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 크기·노출·스타일·전환               | [style.css](../ts/src/style.css)의 토큰과 관련 selector                                                  |
| 범위 유지·장력·좌표 변환            | [scroll-physics.ts](../ts/src/scroll-physics.ts)                                                         |
| 핸들·막대 공통 timeline과 본문 이동 | [transcript.tsx](../ts/src/transcript.tsx)                                                               |
| 가상 높이·행 측정·읽는 anchor       | [virtual-layout.ts](../ts/src/virtual-layout.ts), [virtual-messages.tsx](../ts/src/virtual-messages.tsx) |
| 고정 입력의 노출·유지·이동          | [pinned-prompt.tsx](../ts/src/pinned-prompt.tsx)와 transcript의 jump 처리                                |
| Latest의 방향별 노출                | [app.tsx](../ts/src/app.tsx)의 읽는 이동 처리                                                            |

`messageMap`의 변환은 단조이며 역변환이 가능해야 한다. `RowKnot`은 행 높이가
바뀌어도 현재 읽는 행 내부의 비율을 보존한다. `history-shift`는 휠 목표와 본문
픽셀 좌표에, `mapping-shift`는 핸들 범위와 메시지 좌표에 적용한다. 두 좌표계를
섞으면 페이지 경계에서 막대가 흔들린다.

휠/드래그가 본문을 움직인 즉시 `reading-move`로 가상 목록의 anchor를 갱신한다.
브라우저의 나중 scroll 이벤트만 기다리면 ResizeObserver가 이전 프레임의 위치를
복원할 수 있다. 캐시 경계나 높이만 바뀌면 범위를 그대로 보존하고, 재배치는 실제
읽는 위치의 이동 방향으로만 허용한다. 막대는 seq를 key로 유지하고, 레일 밖에서도
캐시에 남은 노드는 유지해야 범위 교체 애니메이션이 이어진다.
본문에 별도의 CSS `scroll-behavior: smooth`를 추가하면 이 보간과 겹치므로 사용하지
않는다. 키보드 탐색과 명시적인 이동은 진행 중인 휠 보간을 중단한다.

## 고정 입력 overlay

고정 입력은 가상 목록 밖에서 제목 바로 아래, 대화 열과 같은 폭으로 표시한다.
대상이 바뀌어도 상자의 위치는 본문 스크롤 좌표와 무관하다. 다음 입력이 이전
상자를 밀어내거나 본문 흐름과 가상 높이에 공간을 추가하지 않는다.

뷰 상단과 다음 사용자 입력의 상단 사이, 그리고 마지막으로 지나간 입력의 하단
사이에 같은 clearance 조건을 적용한다. 가까운 쪽이 충분히 멀어졌을 때만
상자의 하단과 opacity를 함께 서서히 드러낸다. 상단에 걸친 입력은 충분히 멀어진
상태로 취급하지 않는다. 해당 입력이 없는 쪽은 노출을 제한하지 않는다.
완전히 숨긴 동안은 inert/aria-hidden으로 클릭과 focus를 막고, 노출되는 순간부터
등장 전환을 시작한다.

하단이 드러난 상태에서 상단 접근 영역에 마우스가 들어오거나 버튼이 focus를
받으면 전체 상자가 내려온다. 펼침이 시작되면 최소 유지 시간을 보장하고, 이후
pointer와 focus가 떠나도 잠시 유지한다. 재진입하면 접기 예약을 취소하며 이미
펼친 상태에서는 최소 유지 시간을 다시 시작하지 않는다. 유지 중에는 clearance가
바뀌어도 펼친 상태를 보존한다. 예약은 unmount 때 정리한다.

제목 영역 위로 상자를 그리거나 클릭하지 못하게 한다. 접힌 상태의 활성 영역 밖에서는
본문을 계속 조작할 수 있다. 터치는 focus를 통해 펼치고, 긴 입력은 높이를 제한하여
상자 안에서 스크롤한다. Reduced motion에서는 즉시 전환한다.

누르면 유지·이탈 대기와 전환을 취소하고 즉시 숨긴다. 캐시 밖 입력을 읽는 동안에도
숨김을 유지하며, 다시 clearance 조건을 충족해 새로 노출될 때 일반 동작을 재개한다.
원래 입력 상자 위에 여유를 두고 이동하고, 행 재측정 중에도 그 간격을 보존한다.
실제 스크롤이나 새 jump가 시작되면 일반 읽는 anchor로 돌아간다. 입력 시각은 상자
안에 있고 `>`와 본문은 같은 줄이다. 상자 상단을 clearance와 jump의 기준으로 삼는다.

fade는 고정 입력과 스크롤바 아래에서 본문만 배경으로 사라지게 한다. 고정 입력의
표시 방식은 핸들·막대의 좌표나 장력 계산을 변경하지 않는다.

## Latest 툴바 overlay

Latest는 composer toolbar 중앙의 아래 화살표다. Send와 같은 공통 버튼 토큰과
hover 스타일을 사용한다. 절대 위치 overlay로 toolbar 공간을 차지하지 않는다.

처음과 최신 위치에서는 숨긴다. 과거 방향으로 충분히 이동하면 나타나고 최신
방향으로 충분히 이동하면 숨는다. 작은 방향 반전은 누적 이동에서 상쇄하며,
상태가 바뀌면 누적 이동을 초기화한다. 같은 방향으로 이동할 때 반복해서 켜졌다
꺼지거나 작은 방향 반전에 깜빡이지 않는다.

`Transcript.scrolled()`는 실제 읽는 이동을 `onReadingMove`에 전달한다.
`history-shift`가 기준 위치를 보정하므로 캐시 교체·행 재측정·anchor 복원은
이동량으로 세지 않는다. 장력 자체와 같은 scroll 이벤트의 중복 전달도 제외한다.

입력창 뒤에서 위로 올라오고, 숨길 때 다시 그 뒤로 내려간다. 숨긴 slot은
inert/aria-hidden이며 클릭과 focus를 가로채지 않는다. Reduced motion에서는 즉시
전환한다. 클릭은 최신 기록을 불러와 live follow를 재개하고 draft를 보내거나 지우지
않는다. 고정 입력과 마찬가지로 핸들·막대의 공통 물리는 유지한다.

## 회귀 검증

```sh
npm run --prefix ts test
npm run --prefix ts sandbox:build
npm run --prefix ts test:sandbox
```

- `navigation.spec.ts`: 최초 장력 복귀, 휠 정착, Latest 순간 생성과 캐시 교체 중
  막대의 역방향 이동을 검사한다. 고정된 대기 대신 실제 애니메이션 정착을 확인한다.
- `scroll.spec.ts`, `tension.spec.ts`: hover·접근·장력, 핸들과 막대의 공통 진행,
  양 끝의 위상과 핸들 경계를 검사한다.
- `virtual.spec.ts`: 전체 기록 왕복, 캐시/DOM 상한, 작은 최신 근처 이동과 resize anchor.
- `scroll-physics.test.ts`, `virtual-layout.test.ts`: 물리 곡선, 범위 보존, 단조 변환과
  역변환, 재측정 시 읽는 비율 보존.
- `pinned-prompt.spec.ts`: 고정 레이어의 안정성, clearance와 노출, 접근·focus,
  유지·이탈·재진입, 제목 clipping, 즉시 숨김, 이동 anchor, 캐시 밖 조회와 내부 스크롤.
- `latest-toolbar.spec.ts`: 방향별 누적 노출, 작은 반전, 전환, 공통 버튼 geometry,
  숨김 상태의 hit-test와 draft 보존.

회귀 테스트의 표본·허용 오차는 테스트 코드에서 확인한다. 본문 이동량 검사에서는
누적 `history-shift`를 빼고, 놓는 순간의 좌표는 pointerup capture에서 기록한다.
툴 호출 사이에도 장력 이동이 계속되므로 나중 좌표를 시작점으로 삼지 않는다.
