# 웹 디자인 원칙

웹 UI에서 반복해서 선택한 디자인 방향과 그 이유를 정리한다. 새 화면이나
컴포넌트를 만들 때 시각적 부담, 읽기와 조작의 편안함을 판단하는 기준으로 사용한다.
크기·시간·임계값의 source of truth는 코드다. 문서에는 디자인 의도와 경험을 남긴다.

## 읽기와 작업에 집중할 수 있는 화면

대화 내용과 현재 작업이 먼저 눈에 들어오게 한다. 주변 UI는 필요한 정보와 조작을
제공하면서도 본문과 계속 시선을 경쟁하지 않게 한다.

흑백과 회색을 기본으로 사용하고, 밝기와 배치로 중요도를 구분한다. 코드 문법
강조나 터미널 출력처럼 내용 이해에 도움이 되는 색은 차분하게 사용한다. light와
dark에서도 본문, 표면, 부가 정보의 중요도 관계를 유지한다.

작업 중에는 입력창 상단 뒤의 어두운 오로라 빛으로 진행감을 드러낸다. 이 상태 표현은
색을 사용하되 본문과 조작보다 조용하게 두고, 여러 흐름이 자연스럽게 겹치도록 한다.
나타남과 사라짐도 부드럽게 이어지며, 움직임 줄이기에서는 정적인 빛으로 남는다.
빛은 바 전체와 위쪽으로 퍼지되 실제 표면 뒤에서 그린다. 상단 바는 어두운 배경과
blur로 빛을 누르고, 응답 카드는 기본 배경을 투명하게 유지하면서 blur로 뒤의 빛을
부드럽게 걸러 본문의 가독성을 유지한다.
양끝에도 볼륨을 유지하며 여러 색의 덩어리가 같은 중심을 공전하는 클러스터를
겹친다. 중심은 제한된 영역 안에서 자유롭게 움직이고, 공전하는 덩어리는 각자
커졌다 사라지거나 타원으로 변한다. 작은 진한 부분도 넓고 흐릿한 그라데이션
안에서 천천히 이동한다. 모든 변화는 느리게 이어지고, 시작에는 작게 피어나며
종료에는 서서히 수축한다. 대화뿐 아니라 작업과 기타 이벤트 카드에도 같은 blur를
적용한다.
중력 중심은 상단 바 안에 머무르며, 넓게 겹친 클러스터가 양끝까지 빛을 채운다.
일부 덩어리가 사라져도 흐릿한 바탕을 유지하여 빈틈이 생기지 않게 하고,
움직임은 점들이 떠다니는 인상보다 넓은 빛의 표면이 천천히 울렁이는 느낌을 준다.
양옆에서는 빛이 잘리지 않고 바 밖으로 서서히 흐려진다. 빛은 대화와 스크롤 그림자
뒤의 배경 레이어에 머무르며, 구체의 크기나 이동이 페이지 스크롤 범위를 늘리지 않는다.

부가 정보는 작고 조용하게 두고, 자세한 설명은 hover나 focus에서 확인하게 한다.
아이콘과 그래프는 반복되는 글자를 줄이고 정보를 빠르게 훑는 데 사용한다.
의미와 구체적인 값은 설명과 접근성 이름으로 확인할 수 있어야 한다.

## 요소 사이의 공간은 줄이고, 조작에는 여유를 둔다

관련된 요소 사이의 빈 공간을 줄여 정보와 기능을 가깝게 모은다. 사용자가 한눈에
관계를 파악하고 필요한 곳까지 짧게 시선을 옮길 수 있도록 한다.

인터랙션 가능한 영역에는 충분한 padding을 둔다. 글자나 아이콘이 작아도 편하게
누를 수 있게 하고, 컨테이너 끝에 밀착해 보이지 않게 한다. 좁은 gap과 넉넉한
조작 영역을 함께 설계한다. 화면을 조밀하게 만드는 과정에서 클릭과 focus가
불편해지지 않도록 한다.

여백은 역할에 맞게 둔다. 관련 요소 안의 공간은 아끼고, 읽는 본문 주변에는 여유를
둔다. 넓은 화면에서는 읽기 편한 본문 폭을 유지하고 추가 공간을 보조 작업 영역에
사용한다.

## 경계와 위계를 단순하게 만든다

영역을 구분할 때 배치, 간격, 배경의 밝기 차이를 먼저 사용한다. border는 중요한
외곽이나 구분이 필요한 곳에 집중한다. 이미 묶인 컨테이너 안에서 각각의 항목을
다시 테두리로 둘러싸는 nested border는 지양한다.

예를 들어 Question의 외곽이 영역을 구분한다면, 내부 라디오 항목과 Other editor는
배경과 상태로 구분할 수 있다. fieldset 같은 요소의 기본 장식도 전체 화면에 맞춰
정리한다. 목록은 내용과 상태가 드러나게 하고, 디렉터리 순서만 필요한 곳에 가지나
폴더 장식을 추가하지 않는다.

스크롤 경계에서는 본문이 페이지 배경으로 자연스럽게 사라지게 한다. fade를 배경과
같은 색으로 이어서 별도의 띠나 장식으로 보이지 않게 하고, 본문과 입력 영역 사이의
경계를 단순하게 만든다. 조작 버튼과 스크롤 표시는 가리지 않는다.

떠 있는 카드의 배경 blur도 계층을 정돈하는 데 사용한다. 뒤의 본문은 맥락으로
남기되 현재 카드와 시각적으로 경쟁하지 않게 한다. 카드의 내용은 선명하게 유지하고,
코드처럼 자체 구분이 필요한 내용은 내부 표면을 유지한다.

드롭다운은 설정과 대화 도구에서 같은 반투명 표면을 사용한다. 배경색은 옅게 입히고
뒤의 내용을 블러로 흐려 맥락이 비치게 하되, 메뉴의 글자와 조작은 선명하게 남긴다.

대화 응답 사이의 이전 작업 카드는 첫 줄만 남겨 원근감 있는 표면으로 접는다.
배경 blur 없이 완만한 기울기와 간격으로 작업의 맥락을 남기고 대화 본문의 시선 경쟁을 줄인다.
대화 응답과 작업 카드의 표면은 불투명하게 유지한다. 뒤 내용이 비치는 반투명 배경이나
배경 블러를 사용하지 않아, 겹치는 카드의 내용이 현재 읽는 내용과 경쟁하지 않게 한다.
가장 최근 작업 카드는 펼쳐두고, 다음 작업이 나타나면 이전 작업을 접는다.
hover나 키보드 focus에서는 같은 위치에서 앞으로 나와 반듯하게 펼쳐진다.
펼침과 상세보기는 읽던 대화의 위치나 스크롤 범위를 바꾸지 않으며,
상세를 보는 동안 해당 작업은 앞에 남는다. 크기와 시간은 구현의 토큰을 따른다.

## 같은 기준선과 안정적인 배치를 유지한다

관련 정보와 조작은 일관된 정렬 기준을 갖게 한다. 대화와 입력창의 좌우 관계,
머릿말과 본문의 들여쓰기, label과 값의 baseline이 자연스럽게 이어지도록 한다.
둥근 외곽과 안쪽 요소의 곡률도 서로 어울리게 맞춘다.

로고와 글자는 함께 보았을 때 중심이 맞는지를 판단한다. 글자 형태로 생기는
시각적 차이를 고려해 크기와 위치를 보정한다.

값의 길이가 바뀌거나 메뉴가 열려도 익숙한 위치는 유지한다. 드롭다운의 현재 값이
원래 값과 같은 위치에 나타나면 사용자는 조작의 연속성을 느낄 수 있다. 숨겨진
버튼이 나타날 때에도 본문과 다른 컨트롤을 밀지 않는다.

스크롤, 내용 측정, 창 크기 변화에서도 읽던 메시지의 화면 위치를 보존한다.
사용자가 보고 있던 곳과 작성 중인 곳을 다시 찾게 만들지 않는다.

## 평소에는 조용하게, 조작할 때는 분명하게

버튼과 목록 항목은 평소의 장식을 줄이고 hover, focus, 선택 상태에서 반응을
드러낸다. 경계를 계속 추가하기보다 배경과 글자의 밝기로 상태를 표현한다.
부가 버튼은 필요한 맥락에 접근했을 때 보이게 하되, 사용할 수 있다는 단서는 남긴다.

버튼은 누르는 동안 내용이 살짝 줄고, 놓았을 때 실행되며 원래 모습으로 돌아온다.
버튼의 크기나 주변 배치는 흔들리지 않는다. 길쭉한 버튼도 짧은 버튼과 비슷한
강도의 반응으로 느껴지게 한다. 로고와 제목처럼 다른 형태의 요소는 각자의 중심에
맞춰 반응한다.

같은 의미의 동작은 같은 시각 언어를 사용한다. Send, Latest, Close 같은 도구 버튼,
설정의 선택 컨트롤, 응답과 chip의 미리보기를 화면마다 따로 디자인하지 않는다.
키보드 focus에서도 정보를 확인하고 조작할 수 있어야 한다.

입력창, 상세 카드, 설정, 코드와 표, 파일 에디터와 터미널의 스크롤도 같은 핸들
표현을 사용한다. 트랙을 장식하지 않고 평소에는 핸들을 숨기며, 영역에 접근하면
드러내고 핸들 근처에서는 더 분명하게 보여준다. 표시 상태가 바뀌어도 본문과
입력 커서의 배치는 유지한다. 각 영역의 편집·휠·드래그 동작은 그 영역이 담당하고,
핸들의 색과 크기는 공통 CSS 토큰을 기준으로 한다.

## 움직임으로 위치와 관계를 설명한다

애니메이션은 요소가 어디에서 나왔는지, 무엇이 앞에 있는지, 조작이 어떻게 반영되는지
보여준다. 입력창 뒤에서 나타나는 탐색 버튼과 앞 카드 뒤로 물러나는 Question처럼
등장과 이동의 방향에 의미를 둔다.

한 관계를 표현하는 요소들은 함께 움직인다. 스크롤 핸들과 입력 위치 막대가 같은
진행을 나타낸다면 범위 전환과 장력 상태에서도 그 관계를 유지한다. 스크롤할 때
본문이 배경으로 사라지는 정도도 이동에 맞춰 자연스럽게 변한다.

입력에는 빠르게 반응하면서 이동은 부드럽게 이어지고, 사용자가 의도한 위치에
정확히 정착한다. 작은 방향 전환에 UI가 깜빡이거나 고정 요소가 본문을 따라 떨리지
않게 한다. Reduced motion에서도 위치와 상태를 이해하고 조작할 수 있게 한다.

## 임시 정보와 계속해야 할 작업을 구분한다

응답 세부 정보나 chip 미리보기는 잠깐 확인하는 정보다. 다른 항목을 열면 현재
미리보기를 교체하고, 닫은 뒤 오래된 미리보기가 다시 나타나지 않게 한다.

작업 상세는 해당 응답에 이어지는 표면으로 보여준다. 요약의 내용과 위치를 유지하고,
같은 외곽 폭의 상세를 아래에 붙여 관계를 드러낸다. 중복 제목을 반복하지 않고 탭으로
세부 내용을 나누며, 스크롤은 내용 에디터 안에서만 움직인다. 마우스 더블 클릭으로
열어 대화를 읽는 중 우연히 상세가 펼쳐지지 않게 한다. 키보드로도 열고 닫을 수 있다. 탭과 요약·본문 사이에는 관계를 읽을 여유를 두고,
탭의 복사 동작은 보이는 부분뿐 아니라 원문 전체를 대상으로 한다. 상세 밖의 대화
내용을 누르면 읽던 본문으로 돌아갈 수 있게 상세를 닫는다.

Question은 사용자가 답해야 하는 작업이다. 다른 정보가 앞에 떠도 답과 선택을
보존하고, 명시적으로 응답할 때까지 유지한다. 취소는 버튼 안에서 먼저 확인
상태를 보여주고 같은 위치에서 다시 눌렀을 때 실행한다. 마우스나 포커스가
벗어나면 확인을 해제해, 실수로 남겨진 확인 상태가 다음 작업으로 이어지지 않게 한다. 뒤에 남은 Question은 작아지고
어두워져 계층을 드러내며, 필요한 경우 일부를 보여 아직 작업이 남아 있음을 알린다.
질문을 바꿀 때 카드 크기가 흔들리지 않도록 가장 긴 질문을 기준으로 배치한다.
선택지 목록만 스크롤하고 직접 답하는 영역과 제출 동작은 고정해 둔다.
많은 내용을 읽어야 할 때는 카드를 대화 영역의 사용 가능한 높이로 확대한다.
같은 버튼이나 좌우 빈 공간으로 원래 크기로 돌아오며, 답과 입력 상태는 유지한다.
확대 중에는 대화를 스크롤해도 카드가 입력창 뒤로 물러나지 않는다.
카드 전체의 어두운 반투명 표면과 블러로 뒤의 맥락을 조용히 드러내고,
경계는 카드 외곽에 모으고 본문은 border 없는 별도 내부 컨테이너로 묶는다.
본문은 카드의 좌우로 이어지고 같은 곡률을 사용하며, 더 어두운 선택지와
배경을 구분한다. 질문 문장에는 컨테이너와 선택지 사이 읽을 여유를 둔다.
직접 답변을 작성하면 편집 영역의 선택 상태도 표시하며,
완료 아이콘이 바뀌어도 버튼과 아이콘의 정렬은 유지한다. 질문 탭은
완료 여부를 드러내고, 모든 답변이 준비되어야 제출할 수 있다. 대화를 읽기 위해
스크롤하면 질문 카드는 입력창 뒤로 물러나 배경에 녹아들며, 가까이 다가가거나
키보드로 포커스하면 다시 전면에 올라온다. 이 과정에서 답변과 편집 상태를 유지한다.

겹친 카드의 계층 표현은 상황에 맞게 조절한다. 앞 카드가 작아 뒤 카드가 충분히
보이면 불필요한 위치 이동을 줄이되, 밝기와 크기로 앞뒤 관계는 계속 구분한다.

## 편집 경험과 시각적 일관성을 함께 유지한다

대화 입력과 Question의 Other는 같은 작은 텍스트 에디터 경험을 제공한다. 줄번호,
고정폭 글꼴, 들여쓰기, 코드 강조와 paste chip이 맥락이 바뀌어도 같은 방식으로
동작하게 한다. 파일 보기와 settings editor도 공통 표면과 편집 규칙을 공유한다.

보여주는 형태가 바뀌어도 원문, 커서, 선택과 Undo를 보존한다. 테마 변경이나
보조 패널의 접힘으로 작성 중인 내용과 작업 상태를 잃지 않게 한다.

공통 컴포넌트는 모양뿐 아니라 조작의 일관성도 유지한다. 화면의 밀도와 역할에
따른 차이가 필요하면 공통 규칙 안에서 variant로 표현한다.

## 변경할 때의 판단 기준

- 본문과 현재 작업이 먼저 보이고, 부가 UI의 시각적 부담이 줄었는가.
- 관련 요소 사이의 공간을 줄이면서도 편하게 누르고 focus할 수 있는가.
- 경계와 위계를 배치·배경으로 표현하고, 중첩 장식을 줄였는가.
- 값과 상태가 바뀌어도 정렬 기준, 읽던 위치와 편집 상태가 유지되는가.
- 움직임이 위치와 관계를 설명하고, 작은 변화에도 안정적으로 반응하는가.
- 같은 조작을 다른 화면에서도 익숙하게 사용할 수 있는가.

디자인 수치는 [style.css](../ts/src/style.css)와 [theme.css](../ts/src/theme.css)의
토큰을 기준으로 한다. 스크롤·노출·애니메이션처럼 동작에 속한 수치는 해당 구현에서
관리한다. 문서에 상수나 기본값을 복사해 별도의 기준을 만들지 않는다.

화면별 경험과 동작은 [스크롤 경험 문서](web-conversation-scroll.md),
[설정 문서](web-settings.md), [웹 sandbox 문서](web-sandbox.md)에서 확인한다.
[Storybook](storybook.md)에서 공통 요소를 살피고, sandbox에서 실제 화면의 조합과
전환이 이 방향에 맞는지 확인한다.
