# v0.1.12

웹이 대화를 서버가 축약한 행으로 읽습니다. 같은 대화를 클라이언트가 한 번 더 축약하던 구현이 사라졌습니다.

## 업그레이드

```sh
cxz use v0.1.12      # 또는 cxz use @stable
```

Manager와 프로젝트 runtime을 함께 업데이트하세요. `cxz use`는 둘을 같은 전환에서 올리므로 별도 조치가 필요하지 않습니다.

이번 버전의 웹 UI는 프로젝트 runtime이 **v0.1.11 이상**이어야 대화를 표시합니다. 그보다 오래된 runtime은 읽기용 행 스트림(`SessionService.Rows`, v0.1.11 추가)을 제공하지 않으며, 웹은 기록을 직접 축약하던 경로를 더 이상 갖고 있지 않습니다. 이 경우 대화 대신 "해당 프로젝트 runtime을 업데이트하세요"가 표시됩니다. TUI는 영향이 없습니다.

기존 대화는 그대로 보입니다. 저널이 원본이고, 읽기용 색인은 필요할 때 저널에서 다시 만들어집니다.

## 대화 읽기

같은 대화를 읽는 축약이 둘이었습니다. 서버는 페이징된 기록을 행으로 축약하고, 웹은 실시간으로 도착하는 기록을 **다시** 축약했습니다. 그래서 같은 행이 두 가지 형태로 존재했고, 한쪽에만 맞춘 변경이 다른 쪽을 조용히 어긋나게 만들 수 있었습니다.

- 웹이 행을 스트림으로 받습니다. 도구의 호출·출력·결과는 서버에서 이미 한 행으로 합쳐져 상태(working·완료·실패)를 싣고 오며, 끝난 턴의 지표는 그 응답 행에 붙어 옵니다. 승인 요청은 도구 행의 상태로, 질문의 답변은 질문 행 안으로 접혀 옵니다.
- 턴이 완료되면 그 응답 행이 다시 발행되고 클라이언트는 행을 갈아끼웁니다. 읽는 쪽이 "어느 기록이 어느 행인지"를 판단하지 않습니다.
- 실행 상태·대기 입력·대기 중 승인과 실행 중 도구의 출력은 기존 이벤트 스트림이 계속 나릅니다. 두 스트림이 각각 한 가지 일을 합니다.
- 도구 카드를 펼치면 그 도구의 원본 기록을 그때 가져옵니다. 행은 출력 바이트를 싣지 않습니다. 실행 중에 카드를 펼쳐둔 경우 출력은 펼친 시점의 내용으로 보이며, 이전부터 페이징된 기록은 같은 동작이었습니다.

축약을 담당했던 두 파일에서 190줄이 사라지고 76줄이 들어왔습니다. 표시되는 내용은 바뀌지 않습니다.

## 디자인 샌드박스

- **Tool activity** 시나리오를 추가했습니다. 도구의 호출·실행 중 출력·결과를 실제 에이전트와 같은 형태로 발행하므로, 도구 카드를 실제 투영에서 렌더링한 상태로 볼 수 있습니다.
- 시뮬레이션의 도구 기록에 실행 식별자를 부여했습니다. 식별자가 없는 기록은 어느 도구의 것인지 말하지 않으므로 도구로 취급되지 않습니다.

## 내부

- 기록을 행으로 바꾸는 동작의 검증을 구현이 있는 쪽으로 옮겼습니다: 승인을 거쳐 완료로 가는 도구 행, 거부된 승인과 0 아닌 종료 코드, 실행 식별자가 run 경계를 넘지 않음, 출력이 청크마다 행을 재발행하지 않음, 잘린 기록 경계의 결과가 그대로 읽힘.
- Storybook 픽스처가 런타임이 보내는 행을 사용합니다. 상세 보기용 원본 기록은 따로 제공하므로, 카드를 펼쳐 출력을 가져오는 경로도 함께 검증됩니다.
