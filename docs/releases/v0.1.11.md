# v0.1.11

파일 업로드를 모든 클라이언트가 같은 raw HTTP 경로로 보내도록 통일하고, 대화를 읽는 투영을 스트림으로 제공하는 `Rows`를 추가했습니다.

## 업그레이드

```sh
cxz use v0.1.11      # 또는 cxz use @stable
```

Manager와 프로젝트 runtime을 함께 업데이트하세요.

이번 버전은 `SessionService.Upload` RPC를 제거합니다. **`tcp`/`mtls` relay로 연결한다면 클라이언트와 Manager·relay를 함께 업데이트해야 파일 업로드가 동작합니다.** 구버전 클라이언트는 relay 연결에서 제거된 RPC를 호출하고, 신버전 클라이언트는 `/attachments/`를 제공하지 않는 구버전 relay에 본문을 보내며, 어느 쪽도 다른 경로로 되돌아가지 않습니다. `local`·`unix`·`ssh` 연결과 브라우저는 이미 raw HTTP를 쓰고 있었으므로 영향이 없습니다.

프로젝트 상태 볼륨과 저장된 첨부는 유지합니다. supervisor 프로토콜과 상태 스키마는 바뀌지 않았습니다.

## 파일 업로드

업로드 경로가 둘이었습니다. 브라우저와 `local`·`unix`·`ssh` 연결은 raw HTTP 본문을 보내고, relay 연결과 WASM sandbox는 256 KiB protobuf 메시지 스트림을 보냈습니다. 경로가 둘이면 파일명·크기·run 검사도 둘이고, 실제로 sandbox의 검사는 서버의 검사와 따로 구현돼 있었습니다.

- 이제 모든 클라이언트가 같은 요청을 만들어 같은 핸들러에 도달합니다. sandbox가 거절하는 파일명은 실제 서버가 거절하기 때문에 거절되며, 상태 코드와 JSON도 같습니다.
- `tcp`/`mtls` relay가 호출 옆에서 파일 본문을 나릅니다. 포트를 더 열지 않고 경로로 분기하며, 인증은 그 연결의 호출이 이미 쓰는 자격증명(평문 표면의 토큰, mutual TLS의 클라이언트 인증서)을 그대로 씁니다. 본문을 읽기 전에 인가하므로 거절되는 업로드가 전송 비용을 먼저 치르지 않습니다.
- WASM sandbox는 POST할 소켓이 없으므로 worker의 메시지 채널로 본문을 옮기고, Go 쪽이 같은 핸들러에 넘깁니다.
- relay 연결의 업로드 비용이 측정상 크게 줄어듭니다. 64 MiB 단일 전송 기준 처리량 528 → 849 MB/s, 업로드당 CPU 231 → 100 ms, 할당 131.72 → 0.13 MiB, GC 11회 → 0회이며, 동시 4건에서는 2.11배입니다.
- 첨부 엔드포인트에 닿을 수 없는 연결 — Manager의 `daemon.sock`이 아닌 unix 주소, 자격증명을 갖지 않은 relay — 은 조용히 RPC로 되돌아가는 대신 업로드할 수 없다고 보고합니다.

자세한 경로와 측정은 [첨부 데이터 경로 문서](../attachment-data-path.md)를 참고하세요.

## 대화 읽기 API

`SessionService.Rows`를 추가했습니다. `Transcript`가 페이지로 주는 읽기용 투영을 스트림으로 주며, `Events`와 역할이 갈립니다 — `Events`는 저널에 기록된 그대로의 기록을 나르고(파생이 읽는 쪽), `Rows`는 사람이 읽는 행을 나릅니다.

- 커서가 기록이 아니라 **행의 버전** 위에 있습니다. 턴이 끝나 지표가 응답 행에 접히면 그 응답 행이 다시 발행되므로, 정정이 정정 대상 뒤에 도착하고 읽는 쪽은 행을 교체하기만 하면 됩니다.
- 스트림으로 받은 행과 나중에 페이징한 같은 행이 같은 바이트임을 테스트로 고정했습니다. SQL 인덱스와 sandbox의 인메모리 투영 양쪽에서 확인합니다.
- 아직 이 API를 쓰는 클라이언트는 없습니다. TUI와 웹이 각각 기록을 행으로 축약하는 구현을 들고 있고, 그 중복을 걷어내기 위한 기반입니다 ([#155](https://github.com/lesomnus/cxz/issues/155)).

## 정리

- 모델 카탈로그 선택기가 저널을 훑지 않습니다. `SessionService.Models`가 카탈로그와 그 run·시각을 돌려주므로, 구버전 Manager를 위해 남아 있던 역방향 스캔을 제거했습니다.
- sandbox 브라우저 테스트의 부팅 데드라인 노브가 실제 부팅이 들어갈 수 있는 값을 받습니다. 강제된 스톨을 기다리는 데 쓰던 시간이 줄어 개발 중 테스트가 20.7초 빨라집니다. 제품 동작에는 영향이 없습니다.
