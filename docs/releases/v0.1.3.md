# v0.1.3

v0.1.2 이후 main에 쌓인 작업을 모두 담은 릴리즈입니다. 자동 업데이트, 보조 AI, 공유 프로젝트 메모리, MCP 관리, 히스토리 보존 한도, 읽을 수 있는 기본 devcontainer, 편집 가능한 입력창이 이번에 처음 정식 버전으로 공개됩니다.

## 업그레이드: v0.1.2에서는 자동으로 올라오지 않습니다

이 릴리즈는 상태 스키마 2를 사용합니다. 자동 업데이트는 스키마가 같은 빌드만 적용하므로, v0.1.0~v0.1.2(스키마 1)에서는 릴리즈가 거부됩니다. 진행 중인 작업을 마친 뒤 클라이언트와 설치를 관리하는 호스트에서 각각 실행합니다.

```sh
cxz use --unpin                              # 버전이 고정되어 있으면 먼저 해제합니다
cxz self-update --client-only --ref v0.1.3   # 스키마 검사를 거치지 않고 새 클라이언트만 설치합니다
cxz use v0.1.3                               # 새 클라이언트로 Manager·Runtime·Supervisor를 교체합니다
```

`cxz use`는 idle을 기다리지 않고 강제로 재시작하므로 진행 중인 작업은 중단됩니다. 대화·계정·모델은 유지되고 마지막 입력을 다시 보내지 않습니다. 프로젝트 컨테이너와 데이터 볼륨은 유지됩니다. Linux 호스트의 `self-update`는 Docker Buildx로 소스를 빌드하고, Windows 프런트엔드는 게시된 빌드를 내려받으며 자기 설치만 교체하므로 연결된 Linux 호스트는 따로 올려야 합니다.

`cxz.db`, 세션 저널, 프로바이더 프로필은 지우지 마세요. 새 Runtime은 스키마 1과 2를 모두 읽고, 필요한 테이블을 추가한 뒤 체크포인트를 쓰기 전에 상태를 스키마 2로 표시합니다. 보존 한도를 끄더라도 형식 변경은 되돌아가지 않으므로, v0.1.2 이하로 복귀할 가능성을 남기려면 먼저 상태를 백업하세요.

이미 `@edge`를 쓰고 있었다면 스키마는 이미 2입니다. `cxz use v0.1.3` 또는 `cxz use @stable`만 실행하면 됩니다.

## 자동 업데이트

v0.1.2에서 "별도 PR"로 남겨둔 자동 업데이트가 포함되었습니다. 수정되지 않고 게시된 `main`의 후손인 빌드만, 선택한 채널에서 스스로 갱신합니다. 확인은 하루 한 번이고 적용 대기열은 30초마다 안전 조건을 다시 평가합니다. 자동 적용은 다운그레이드하지 않습니다.

교체는 항상 작업보다 뒤입니다. Manager는 설치의 모든 세션이 안전하게 idle일 때, 프로젝트 Runtime은 그 프로젝트의 세션이 idle일 때, Supervisor와 Agent는 5분 idle 후, TUI는 5분간 입력이 없고 초안·모달·첨부·진행 중 요청이 없을 때 교체됩니다. 도구 실행, 대기 중인 승인, 판단할 수 없는 상황은 모두 교체를 미룹니다. 멈춰 있는 세션은 업데이트하려고 깨우지 않습니다.

```sh
cxz self-update status|check|enable|disable [--server]
```

`--server`는 Linux 호스트에서 Manager 자신의 정책을 다룹니다. 원격 프런트엔드를 붙여도 서버 정책은 바뀌지 않습니다.

## 보조 AI

대화 안에 요약과 다음 메시지 제안이 표시됩니다. 입력창이 비어 있을 때 `→`를 누르면 보이는 제안이 편집 가능한 입력으로 들어옵니다. 전용 계정과 모델을 대화형 로그인과 카탈로그에서 고릅니다.

```sh
cxz ai login ACCOUNT
cxz ai models ACCOUNT
cxz ai set summary    --account ACCOUNT --model MODEL [--effort EFFORT]
cxz ai set suggestion --account ACCOUNT --model MODEL [--effort EFFORT]
cxz ai status SESSION
cxz ai cancel SESSION
```

요약은 마크다운으로 렌더합니다. 보조 응답은 1 MiB까지 받고, 그보다 긴 응답은 실패로 처리하는 대신 잘렸다고 알리고 보여줍니다. 보조 프롬프트는 읽을 수 있는 파일입니다.

## 공유 프로젝트 메모리

프로젝트 단위로 공유되는 메모리를 MCP 서버로 제공하고, TUI에서 스냅샷을 확인할 수 있습니다. 변경은 커서로 탐색하므로 에이전트가 전체를 다시 읽지 않습니다. 메모리 사용 지침은 빌드에 포함된 문서에서 나옵니다.

## MCP 관리

전역 기본값과 프로젝트별 override를 한 런타임에서 관리합니다. 원격 클라이언트와 Windows에서도 같은 명령을 씁니다.

```sh
cxz mcp list|add|remove|enable|disable|inherit
cxz mcp logs ID --project PROJECT --session SESSION
cxz mcp restart ID --project PROJECT --session SESSION
```

연결 상태를 화면에 표시하고, Codex의 elicitation을 포함한 확인 요청을 질문 UI에서 바로 답합니다. 승인 요청은 누가 요청한 것인지 함께 보여주고, 이미 끝난 요청도 열어서 내용을 확인할 수 있습니다. 스킬도 같은 모양입니다(`cxz skill ...`).

## 히스토리와 보존 한도

입력·응답·도구 호출·승인·상태 변경은 세션별 저널에 추가되고, 화면은 그 저널을 그린 결과입니다. 서로 무관한 두 예산이 있습니다.

| | 위치 | 기본값 | 범위 |
|---|---|---|---|
| 서버 보존 | Manager | 세션당 100 MiB | 디스크의 저널 |
| 클라이언트 윈도 | TUI | 10 MiB 또는 200턴 | 프런트엔드가 메모리에 들고 있는 양 |

`Ctrl+.` 에서 둘 다 조정합니다. 서버 보존은 한도를 넘으면 안전한 idle 시점에 가장 오래된 완료된 턴부터 지우고 체크포인트를 남깁니다. 클라이언트 윈도를 줄이는 것은 아무것도 지우지 않습니다. 에이전트의 한 메시지는 16 MiB로 제한하며, 그보다 긴 메시지는 세션을 죽이지 않고 도착한 바이트를 기록하고 잘렸다고 보고합니다.

## 프로젝트 환경과 devcontainer

기본 devcontainer가 Go 개발 이미지, 비root 사용자, 자원 한도를 가진 읽을 수 있는 Compose 템플릿이 되었습니다. 셸 히스토리 볼륨은 프로젝트별이고 Go 모듈·빌드 캐시는 머신 전체에서 공유합니다. 템플릿의 Compose 파일에도 치환이 적용되고 호스트 작업 공간 경로를 가리키는 `${cxz:workspace}`가 추가되었습니다. 공유 Compose override는 이제 image·Dockerfile 기반 devcontainer에도 번역해서 적용하고, 대응물이 없는 항목은 이름을 들어 거부합니다.

```sh
cxz devcontainer render [PROJECT]           # 실제로 적용된 구성을 디렉터리로 씁니다
cxz devcontainer docker-compose [PROJECT]   # 병합된 Compose 구성만 출력합니다
cxz gitconfig sync                          # 호스트 Git 설정을 실행 중인 프로젝트에 반영합니다
```

호스트의 전역 Git 설정을 프로젝트 컨테이너에 스냅샷으로 넣으므로 에이전트의 커밋이 호스트와 같은 신원과 설정을 씁니다. `include.path`·`includeIf`로 참조된 파일까지 복사하고 경로를 컨테이너 사본으로 다시 씁니다. `cxz up`이 자동으로 스냅샷을 찍고, `cxz gitconfig sync`는 실행 중인 프로젝트를 재시작 없이 갱신합니다. 설정만 복사하며 자격 증명은 옮기지 않습니다(그쪽은 `cxz github sync`입니다). 최신 Docker에서 Compose devcontainer 빌드가 실패하던 문제와, 인자 없이 `devcontainer render`를 실행하면 패닉이 나던 문제를 고쳤습니다.

## 영구 삭제

대화를 실제로 지우는 명령이 생겼습니다. 둘 다 `--yes` 없이는 지우지 않고, 먼저 정확한 대상을 보고합니다.

```sh
cxz project purge PROJECT         # 지울 대상을 먼저 확인합니다
cxz project purge --yes PROJECT   # 이 프로젝트와 cxz가 소유한 데이터를 지웁니다
cxz session purge --dry-run SESSION
cxz session purge --yes SESSION
```

세션을 지우는 것(delete)은 저널을 남겨 복구 가능하지만, `session purge`는 저널·에이전트 프로필·업로드·메모리·기록 자체를 지웁니다. `project purge`는 해당 프로젝트의 컨테이너·소유 볼륨·전용 네트워크와 등록 정보까지 지우고, 호스트 작업 공간·전역 계정·다른 프로젝트·공유 Docker 자원은 건드리지 않습니다.

## 입력창과 대화 화면

작업 중에도 입력할 수 있습니다. cxz가 메시지를 한 건 들고 있다가 에이전트가 받을 수 있는 첫 순간에 넘깁니다. 기다리는 동안 상태 줄에 표시되고, 대기 중인 메시지가 있을 때 두 번째 입력은 거부됩니다.

```sh
cxz session send ID "text"      # 턴 중에는 queued로 답합니다
cxz session cancel ID           # 아직 에이전트가 받지 않은 메시지를 되돌립니다
```

입력창은 키보드와 마우스로 선택·이동할 수 있습니다. 단어 단위 선택, 보이는 줄 기준 Home·End, Shift 선택, 휠 스크롤, 스크롤바를 지원하고 최대 12줄까지 늘어납니다. 붙여넣기 칩은 미리보기에서 편집 가능한 입력으로 펼칩니다.

`/download`로 컨테이너의 파일을 이 클라이언트의 Downloads 폴더로 내려받을 수 있고, 진행률·속도·남은 시간을 표시합니다. 방문한 세션 사이는 `Alt+←`·`Alt+→`로 이동합니다. 프로바이더의 컨텍스트 보고를 요약과 원문으로 정규화해 보여주고, 도구 표시는 마커로 줄이고 더블클릭으로 상세를 엽니다. 실패한 턴은 눈에 띄는 색으로 표시하고, 코드 블록·인라인 코드·프롬프트의 대비를 정리했으며, 터미널 포커스를 따라가고 스피너마다 위상을 달리 둡니다. 중단된 프로젝트는 탐색에서 숨깁니다.
